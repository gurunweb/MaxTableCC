# Изменения 2026-05-12 — управляемость через чат

Большой пакет улучшений: MCP по запросу, авто-публикация файлов, web-apps через `/apps/`, публичные короткие ссылки, скиллы для Next.js + БД, формализованная URL-схема, GC портов, steel-browser интеграция.

## MCP — управление из чата

**Было:** `mcp.template.json` подключал playwright + fetch ко всем чатам всех юзеров. Один файл, не настраивается.

**Стало:** трёхуровневая система с пустым дефолтом.

| Уровень | Файл | Скоуп |
|---|---|---|
| Global | `/etc/cc-bridge/mcp.json` (пусто) | Все чаты всех юзеров |
| Project | `<projectRoot>/.mcp.json` | Все чаты проекта |
| Chat | `<chatDir>/.mcp.json` | Один чат |

При старте Claude [src/lib/mcpMerge.ts](../src/lib/mcpMerge.ts) сливает три уровня (chat > project > global, `null` = explicit disable) в temp-файл и передаёт его через `--mcp-config`. Если итог пуст — MCP не подключаются вовсе (экономия токенов системного промпта).

**Реестр** [config/mcp-registry.json](../config/mcp-registry.json) — whitelist установленных MCP: playwright, fetch, filesystem, postgres, sqlite, github, slack, memory, puppeteer.

**Скилл** [config/skills/mcp.md](../config/skills/mcp.md) описывает Claude'у, как добавить/удалить MCP в нужный `.mcp.json` через текстовые команды юзера («подключи playwright к этому проекту»).

**Playwright per-user:** `--user-data-dir=/workspaces/{email}/playwright-profile` подставляется автоматически (изоляция cookies на shared-сервере). Если в env задан `playwrightCdpEndpoint` (через steel-browser) — переключается в attach-режим к headed-chromium.

## Auto-publish hook

Раньше Claude был обязан сам вспомнить вызвать `/publish` после создания файла — иногда забывал. Теперь:

- [hooks/cc-auto-publish.sh](../hooks/cc-auto-publish.sh) — PostToolUse-хук, реагирует на `Write|Edit|MultiEdit|NotebookEdit`.
- Фильтрует по расширению (картинки, видео, аудио, html/pdf/csv/zip/...).
- Дёргает `POST http://127.0.0.1:8080/internal/publish` с `chatId=$CC_CHAT_ID`.
- Отдаёт URL обратно через `hookSpecificOutput.additionalContext` — Claude видит «Файл outputs/X опубликован: URL» в контексте.

[src/lib/permissionHook.ts](../src/lib/permissionHook.ts) → новый `installHooks(workdir, {safe})` ставит PostToolUse всегда, PreToolUse permission-check только в safe-режиме. [claudeRunner.ts](../src/lib/claudeRunner.ts) вызывает его для всех режимов (auto/plan/safe).

## Публичные короткие ссылки `/p/:slug`

В БД INSERT в `public_links` был, но обработчика для отдачи файла не было — `public:true` молча ломался.

- [src/routes/publicLink.ts](../src/routes/publicLink.ts) — `GET /p/:slug` (без auth, public).
- Резолвит slug → chat.workdir + relative path. Проверяет `expires_at`.
- При `CC_USE_XACCEL=1` отдаёт через `X-Accel-Redirect` на internal nginx location `/_files_internal/`. Иначе стримит сам.
- Nginx-location `^~ /p/` проксирует в node, `/_files_internal/` (internal-only) — alias на `/`.

## Web-apps через `/apps/{slug}/` (reverse-proxy)

Раньше: nginx-location `/apps/` возвращал заглушку `503 Webapp routing pending`.

Теперь:

- Миграция [003_projects_app_port.sql](../src/db/migrations/003_projects_app_port.sql) — колонка `projects.app_port`.
- `createProject()` резервирует порт, `pickAppPort()` учитывает и `chats.app_port`, и `projects.app_port`.
- Resolver [src/routes/resolveApp.ts](../src/routes/resolveApp.ts) — `GET /internal/resolve-app/{project|chat}/:id` → `X-App-Port` заголовок.
- Nginx использует `auth_request` к resolver'у, читает `X-App-Port`, проксирует:
  - `/apps/{project-slug}/...` → `127.0.0.1:{projects.app_port}`
  - `/apps/c/{chatId}/...` → `127.0.0.1:{chats.app_port}`
- Кастомные error-pages: 404 «приложение не найдено», 502 «процесс не запущен».
- Поддержка WebSocket (`proxy_set_header Upgrade`).
- Новый env `CC_APP_URL` в claudeRunner — готовый URL для Claude (вместо ручной подмены `/files/` → `/apps/`).

## steel-browser (опциональная интеграция)

- Миграция [004_browser_sessions.sql](../src/db/migrations/004_browser_sessions.sql) + таблица в [schema.sql](../src/db/schema.sql).
