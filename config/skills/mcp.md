# /mcp — управление MCP-серверами через чат

MCP-серверы по умолчанию НЕ подключены. Юзер может попросить установить/подключить/отключить — действуй через этот скилл.

## Уровни конфигов

| Файл | Скоуп | Когда применять |
|---|---|---|
| `/etc/cc-bridge/mcp.json` | **Global** — все чаты всех юзеров | Только если юзер явно сказал «подключи ко всем чатам / навсегда» |
| `<projectRoot>/.mcp.json` | **Project** — все чаты этого проекта | «Подключи к проекту», «к этому проекту» |
| `<chatDir>/.mcp.json` | **Chat** — только текущий чат | «Подключи к этому чату» (по умолчанию для одиночных чатов) |

Уровни сливаются при старте Claude: chat > project > global. `null` в значении отключает MCP с предыдущего уровня (например, проект отключает global).

## Реестр доступных MCP

Whitelist в `/etc/cc-bridge/mcp-registry.json`. Поле `servers.<name>` содержит готовый `command`+`args` и описание. Если юзер просит «установить X» — проверь, есть ли X в реестре. Если нет — сообщи юзеру список доступных и спроси.

## Действия

### Подключить MCP к чату/проекту

1. Прочти `/etc/cc-bridge/mcp-registry.json`, найди запись по имени.
2. Открой целевой файл (`./.mcp.json` для текущего workdir или `chats/$CC_CHAT_ID/.mcp.json`). Если файла нет — создай: `{"mcpServers": {}}`.
3. Добавь в `mcpServers.<name>` объект с `command`, `args`, при необходимости `env`. Если у записи в реестре есть `argsPlaceholder` — спроси юзера или подставь разумный default (например `workdir` = текущая папка).
4. Сохрани файл.
5. Сообщи: «MCP <name> подключен к <scope>. Применится со следующего сообщения в этом чате».

Изменения подхватятся только при следующем запуске задачи — `--mcp-config` Claude читает на старте.

### Отключить MCP

1. Найди соответствующий `.mcp.json`.
2. Удали запись из `mcpServers` или поставь `null` (если хочешь подавить unaserved global).
3. Сохрани.
4. Сообщи юзеру.

### Список подключённых

Покажи содержимое всех трёх уровней (global / project / chat) с пометкой откуда. Используй `cat`, не нужно мерджить — это делает cc-bridge.

### Установка нового MCP (вне реестра)

Если юзер просит конкретный пакет, которого нет в реестре:

1. Сообщи: «Этот MCP вне whitelist. Я могу добавить его в реестр сервера — нужны права root».
2. Не делай `npm install -g` сам — `npx -y <package>` работает без установки (Claude Code запускает по `command` из mcp.json).
3. Если юзер настаивает на постоянной установке — попроси добавить запись в `/etc/cc-bridge/mcp-registry.json` руками (через ssh) и перезапустить сервис.

### Спецификация playwright

`--user-data-dir` для playwright cc-bridge ставит автоматически per-user (`/workspaces/{email}/playwright-profile`) — не указывай его в `.mcp.json`. Cookies/логины каждого юзера живут отдельно.

## Стоимость подключения

Каждый MCP добавляет ~1–5K токенов в системный промпт Claude (описания tools). Не подключай «на всякий случай» — только когда юзер явно попросил.

## Пример: подключить playwright к проекту

Юзер: «подключи playwright к этому проекту».

Действия:
```bash
# 1. Прочитать запись из реестра
cat /etc/cc-bridge/mcp-registry.json | jq '.servers.playwright'

# 2. Записать в project-level .mcp.json (workdir = корень проекта)
cat > ./.mcp.json <<'EOF'
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest", "--browser=chromium"],
      "env": { "DISPLAY": ":1" }
    }
  }
}
EOF
```

Ответ юзеру: «playwright подключен к проекту. С новой задачи я смогу управлять браузером.»
